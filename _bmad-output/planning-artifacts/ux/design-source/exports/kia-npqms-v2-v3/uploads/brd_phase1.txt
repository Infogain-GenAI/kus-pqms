2.2 Business Context
The legacy KPQMS TSB publication process is fragmented across XPLATFORM screens, manual email
chains, and the decommissioned Spotfire/EWS system. KUS PQ engineers manage ~16,970 TSB-related
screen interactions monthly under a framework that cannot integrate with Azure AD, Camunda BPM, or
SAS Visual Analytics.
Phase 1 resolves this by:
Consolidating the TSB lifecycle (draft → review → approval → posting → time tracking) into a single
Camunda-orchestrated workflow
Bringing QIR creation and management onto the same cloud-native platform with shared VIN/dealer
data from INT-01 (AS400) and INT-03 (Siebel)
Enabling the KUS PQ team's SAS VA dashboards via INT-06 outbound data from go-live
Delivering the full Admin Module (ADM) at go-live so user management, master data, workflow
templates, and system configuration are self-service from day one — no dependency on a later phase
for administrative operations
